## Findings

### 1. Accepted grammar is scalar UINT with direct static resource identities

Resource records must be `Buffer<unsigned int>` or `RWBuffer<unsigned int>`, space 0, register 0/1/2, array size 1, kind 10 and component metadata `{i32 0, i32 5}`. Input register 0 maps to record 0, input register 2 to record 1; UAV register 1 is the output. Simultaneous t0/u0 or t2/u2 input collisions reject because they share a logical slot. Handles are resolved by `(resource class, range ID)` and their constant register index must agree; resource-list ordering is not the binding identity. [Resource checks](../tests/dx12/dxil_origin_transform.hpp#L65), [mapping](../tests/dx12/dxil_origin_transform.hpp#L78), [handle checks](../tests/dx12/dxil_origin_transform.hpp#L143).

Float, signed int, UNORM and vector resources are outside this grammar: the accepted class spelling and component metadata are fixed, module types are whitelisted, and extraction accepts only component 0. Dynamic handle indices, nonuniform handles, arrays, other spaces, PHI/select provenance and general input control flow are also outside it. This is source-level acceptance/rejection analysis; it does not claim a fresh eight-type full-container matrix passed. [Types](../tests/dx12/dxil_origin_transform.hpp#L74), [module envelope](../tests/dx12/dxil_origin_transform.hpp#L101), [constant handles](../tests/dx12/dxil_origin_transform.hpp#L143), [instruction whitelist](../tests/dx12/dxil_origin_transform.hpp#L189).

The output u1 store is copied without origin/count guarding. Input loads, stores and integer add atomics receive logical-bound and unsigned-add-wrap guards; invalid loads/atomics merge zero, invalid stores skip the write. Scalar resource support must not be inferred from the four-value DXIL return/store carrier: the read extraction whitelist remains component 0 and the store matcher fixes mask 15. [Access classification/output bypass](../tests/dx12/dxil_origin_transform.hpp#L153), [guards and merge](../tests/dx12/dxil_origin_transform.hpp#L164), [extraction](../tests/dx12/dxil_origin_transform.hpp#L189).

### 2. Full-container validation exists, but is not production lowering

The tool accepts one SM6.0 compute DXIL program and a finite part whitelist; embedded root signatures/debug/library or unknown parts do not pass that whitelist. It validates input, disassembles, optionally lowers, assembles a full container, validates output and inspects it again. Text identity is checked only in the non-lowering mode; neither branch proves byte-identical auxiliary chunks or semantic equivalence of arbitrary transformed programs. [Container inspection](../tests/dx12/dxil_roundtrip.cpp#L96), [validation pipeline](../tests/dx12/dxil_roundtrip.cpp#L160), [identity condition](../tests/dx12/dxil_roundtrip.cpp#L183).

Existing parser tests use synthetic strings and check rejection leaves the output unchanged. They cover dynamic/nonuniform handles, unsupported component metadata, store masks, arrays, spaces, duplicate identities/slots and reordered mixed SRV/UAV inputs. Their own result label explicitly excludes DXIL/GPU validation. Thus they complement, rather than replace, the fresh real-container matrix and additional parser negatives. Test pointers here refer to the completed working changes. [Synthetic fixture](../tests/dx12/dxil_origin_transform_test.cpp#L5), [negative oracle](../tests/dx12/dxil_origin_transform_test.cpp#L47), [negative cases](../tests/dx12/dxil_origin_transform_test.cpp#L56), [dual-input cases](../tests/dx12/dxil_origin_transform_test.cpp#L86), [result label](../tests/dx12/dxil_origin_transform_test.cpp#L122).

### 3. Hidden root metadata is a test ABI with explicit ownership

Lowering adds b0/space1 and one or two 16-byte origin/count records. Existing CBVs/samplers reject at the resource-root grammar. That restriction avoids a conflict within this corpus; it is not a production reservation policy for application root signatures. [Resource-root restriction](../tests/dx12/dxil_origin_transform.hpp#L51), [record loads](../tests/dx12/dxil_origin_transform.hpp#L127), [inserted metadata](../tests/dx12/dxil_origin_transform.hpp#L200).

The native alias probe explicitly constructs a two-parameter root (UAV table plus b0/space1 CBV), writes an origin-buffer GPU address into its root argument buffers, and destroys the root after the diagnostic loop. The compiler helper borrows the root, keeps file bytes alive during `IRBytecodeOwnershipNone` compilation, returns a strong PSO and destroys compiler/intermediate objects on cleanup. This is a bounded ownership example; it does not establish production submission metadata lifetime. [Root construction/lifetime](../tests/dx12/msc_static_alias_probe.c#L128), [address encoding](../tests/dx12/msc_static_alias_probe.c#L83), [helper ownership](../tests/dx12/msc_probe_compile.h#L7), [cleanup](../tests/dx12/msc_probe_compile.h#L43).

Production root objects copy application bytecode and query MSC layout from that same blob. Compute PSO creation initializes that layout and passes the root blob plus original CS to conversion. Argument encoding walks the existing layout and copies application staging/table addresses; it does not synthesize the probe's origin/count CBV. Any future integration must define separate application/compiler root identities, reserved-space collision policy, parameter remapping and embedded-root handling. This is an inferred design requirement from the mismatch, not an implemented feature. [Owned root blob](../src/d3d12/d3d12_root_signature.cpp#L369), [MSC layout](../src/d3d12/d3d12_root_signature.cpp#L470), [compute root selection](../src/d3d12/d3d12_pipeline_compute.cpp#L71), [argument encoding](../src/d3d12/d3d12_command_list.cpp#L2827).

### 4. Production descriptor lifetime infrastructure does not include origin metadata

Production typed-view construction clears the MSC descriptor first, rejects zero count or unaligned byte offset, then creates an exact aligned texture view and packs address/resource-ID/length. It does not round the native origin or generate the probe's per-input padding records. [Typed view](../src/d3d12/d3d12_descriptor_heap.cpp#L176).

Descriptors and referenced resources/views are copied coherently under a mutex; copies propagate typed-view references and payloads. Static missing views fail recording, while submission-time resolution rejects missing views and retains native resources. These are real existing lifetime mechanisms. They do not yet establish an origin/count record synchronized with descriptor copies, heap rebinding, allocation changes and static-versus-volatile observation points. A future origin implementation must extend the same coherent payload/reference relationship and prove GPU completion lifetime, rather than attaching mutable CPU metadata alone. [Snapshot](../src/d3d12/d3d12_descriptor_heap.cpp#L425), [copy](../src/d3d12/d3d12_descriptor_heap.cpp#L659), [recording gate](../src/d3d12/d3d12_command_list.cpp#L3190), [submission retention](../src/d3d12/d3d12_command_list.cpp#L3262).

### 5. Cache integration requires a versioned transform contract

MSC conversion keys already include conversion/API/target/binding versions, shader bytes, global/local root hashes and compile inputs; memory and persistent hits return before compilation. CompileDXIL forwards supplied bytes/root through the MSC thunk, without this test transform. PSO persistence separately hashes application root/shader inputs and its environment. Thus existing caches are not inherently unsafe, but do not describe a new lowering policy or hidden-root mapping. Future integration needs explicit transform/ABI versioning and reproducible shader/root/metadata-layout identity, including cache-hit/miss equivalence and invalidation tests. [Conversion key versions](../src/d3d12/d3d12_shader_converter.cpp#L89), [shader/root hashes](../src/d3d12/d3d12_shader_converter.cpp#L158), [cache early returns](../src/d3d12/d3d12_shader_converter.cpp#L1658), [compile forwarding](../src/d3d12/d3d12_shader_converter.cpp#L1235), [PSO root hash](../src/d3d12/d3d12_pipeline_persistence.cpp#L221), [PSO key](../src/d3d12/d3d12_pipeline_persistence.cpp#L695).

### 6. Native static alias evidence is not D3D12 barrier proof

The diagnostic uses R32Uint views of one backing buffer, independent per-view records and three native dispatches. It inserts Metal buffer/texture memory barriers, waits for completion and compares full backing bytes plus phase outputs against CPU expectations; its swapped-count control changes logical counts. It does not create D3D12 resources, command lists or barriers. [Format/backing](../tests/dx12/msc_static_alias_probe.c#L7), [independent records](../tests/dx12/msc_static_alias_probe.c#L51), [native dispatch/barriers/readback](../tests/dx12/msc_static_alias_probe.c#L88), [negative-control verdict](../tests/dx12/msc_static_alias_probe.c#L147).

The existing alias report records a 2026-10-01 native run and explicitly excludes production metadata and D3D12 barrier translation. Those numbers are prior reported evidence only; this audit neither reran nor independently refreshed them. Production has distinct UAV memory-barrier encoding and aliasing encoder-boundary invalidation; a successful native barrier experiment cannot validate those translation paths, descriptor reuse or cross-command-list/queue visibility. [Prior dated results](D3D12_DXIL_STATIC_ALIAS.md#L50), [prior limitations](D3D12_DXIL_STATIC_ALIAS.md#L89), [production barrier branches](../src/d3d12/d3d12_command_list.cpp#L4337).
